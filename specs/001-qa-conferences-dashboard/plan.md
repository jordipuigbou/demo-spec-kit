# Implementation Plan: QA Conferences Dashboard Spain

**Branch**: `001-qa-conferences-dashboard` | **Date**: 2026-06-06 | **Spec**: [spec.md](spec.md)

## Summary

Build a single-page Next.js 16 (App Router, Turbopack) web application that renders a responsive card grid of mocked QA and testing conference events in Spain. Each card displays the event name, human-readable date, city, and a thematic image with graceful fallback. All data lives in a static TypeScript file — no backend, no authentication, no filtering.

## Technical Context

**Language/Version**: TypeScript 5.x with Next.js 16.x LTS (App Router, React 19.2)

**Primary Dependencies**:

- `next` ≥16.2.7 — framework (user-specified; 16.x LTS, Turbopack stable by default)
- `react` / `react-dom` ≥19.2 — UI library
- `tailwindcss` 4.x — utility-first styling
- `vitest` ≥4.1 + `@vitejs/plugin-react` + `@testing-library/react` — unit/component tests (4.1 adds `context.annotate` for structured AC traceability)
- `@vitest/coverage-v8` — coverage reporting
- `@playwright/test` ≥1.60 — E2E tests
- `jsdom` — DOM environment for Vitest

**Storage**: N/A — all data is static TypeScript constants in `src/data/conferences.ts`

**Testing**: Vitest ≥4.1 (unit + component, `context.annotate` for AC metadata), Playwright ≥1.60 (E2E)

**Target Platform**: Modern browsers (Chrome, Firefox, Safari, Edge — current versions), viewport widths 375 px – 1440 px

**Project Type**: web-application (Next.js frontend only, no backend)

**Performance Goals**: LCP < 2.5 s on a standard broadband connection; no runtime data fetching latency

**Constraints**: Static/mocked data only; responsive from 375 px; image fallback required; no filtering/search UI

**Scale/Scope**: Single page; 7 mocked events

**Structure Decision**: Single Next.js project. No backend, no monorepo. All source lives under `qa-conferences/` at the repository root. App Router chosen as Next.js 15 default; a single server component page renders mocked data synchronously. `EventCard` is a client component (`"use client"`) to handle the image `onError` fallback.
